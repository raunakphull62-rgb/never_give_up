# A3 — HTTP server and fuller HTTP client

## Ambiguity readings (taken as specified, documented here)

- **Reuse, no second path.** `http_serve` binds via `a1_net::tcp_listen`,
  accepts via `tcp_accept_timeout`, reads via `conn_read_line`/`conn_read`,
  writes via `conn_write`, timeouts via `conn_set_timeout`, remote via
  `conn_peer`, close via `conn_close`. Jobs queue on an `a2_threads`
  channel (`chan`/`send`/`recv`/`close` carrying `Value::Conn`); workers
  are OS threads with the A2 shape (8 MiB stack, shared `Arc` module,
  per-thread Klang ids). No raw `TcpListener`/`TcpStream` outside A1, no
  second TLS stack (client reuses the `ureq` rustls + WebPki bundle from
  `stdlib::http`).
- **Null is JSON null everywhere.** `Value::Null` (`is_null`) maps to JSON
  `null` in every JSON this stage produces or parses: `json_decode("null")`
  is `Null`, `json_stringify(Null)` is `"null"`, `http_json(status, Null)`
  has body `"null"`, `{"a": null}` decodes with `is_null(v["a"])`. Bools
  have no runtime value (`Bool` erases to `Int` 0/1), so `true`/`false`
  decode to `1`/`0` and every `Int` encodes as a number (bools do not
  round-trip; the legacy `json` package markers stay for package users).
- **W-SHADOW forces a rename.** The pure-Klang `json` package already
  defines `fn json_parse(text) -> {ok, value, error}` with `$json` markers.
  A same-named native would trip `W-SHADOW` (like `hex_encode` in A1 / B1
  complements). So the fast native is `json_decode(s) -> value` (throws
  `E-JSON-PARSE`), while `json_stringify(v, pretty)` keeps the queue name
  (no package collision). The package works unchanged; handlers use the
  natives for the 1 MB-in-1 s path (measured <1 s, gate-pinned).
- **`http_request` 5 or 6 args.** Queue lists 5
  `(method, url, headers_map, body, timeout_ms)` plus "option to disable"
  redirects. The 6th optional `options` map carries it:
  `{"follow_redirects": 0}` disables (returns the 3xx), `{"max_redirects": n}`
  caps `1..10` (default follow, max 5). Headers are a `Map` (unlike
  `http_post`'s array), response is `{status, headers, body}` with
  lower-case header keys like `http_get`.
- **`route_match` null on no-match.** Returns a params `Map` on match
  (`"/notes/:id"` + `"/notes/42"` -> `{"id": "42"}`), `Null` (`is_null`)
  on no-match. Empty pattern/path or empty `:name` is `E-HTTP-ROUTE`.
- **Render pattern.** Example binds `"0.0.0.0"` with `port` from
  `get_env("PORT")` (`0` = any when unset), polls
  `signal_pending("TERM")` and `"INT"` then `http_stop` (graceful: finish
  in-flight). `PORT_FILE` (test-only) writes the bound port for harness
  discovery; `Render` ignores it.
- **Sandbox: network denies, pure allows.** `http_serve`, `server_port`,
  `http_stop`, `http_request` deny with `E-SANDBOX-NETWORK`.
  `http_json`, `http_text`, `http_redirect`, `route_match`, `json_decode`,
  `json_stringify` are pure (like `is_null`) and stay allowed.
- **`server_port` after stop is closed.** `http_stop` is idempotent (`1`);
  `server_port` on a stopped server is `E-HTTP-CLOSED` (like
  `listener_port` on a closed listener).

## Builtin signatures (exact)

- `http_serve(host: str, port: int, handler: str, options: map) -> Server`
  (`port 0` = any; `handler` names a top-level `fn(req: map) -> map`;
  options `workers` `1..32` default 4, `max_body_bytes` `0..10MB` default
  1MB, `read_timeout_ms` `0..60000` default 10000 (`0` blocks),
  `max_header_bytes` `1024..1MB` default 64KB).
- `server_port(s: Server) -> Int` (`E-HTTP-CLOSED` when stopped).
- `http_stop(s: Server) -> Int` (`1`, idempotent, graceful).
- `http_request(method: str, url: str, headers: map, body: str, timeout_ms: int[, options: map]) -> Map`
  (`method` one of `GET POST PUT DELETE PATCH HEAD OPTIONS`;
  `headers` `str->str` map; `timeout 0..120000` (`0`=30s default);
  `options` `follow_redirects 0/1`, `max_redirects 1..10`; follows up to 5;
  `GET/HEAD/DELETE/OPTIONS` ignore non-empty bodies).
- `http_json(status: int 100..599, v: any) -> Map` (`content-type:
  application/json`, compact body, `Null`->`null`).
- `http_text(status: int 100..599, s: str) -> Map` (`text/plain`).
- `http_redirect(url: str) -> Map` (`302` + `location`).
- `route_match(pattern: str, path: str) -> Map | Null` (`:name` captures,
  trailing slashes ignored, `Null` on no-match).
- `json_decode(s: str) -> value` (`null`->`Null`, `true/false`->`1/0`).
- `json_stringify(v: any, pretty: int) -> Str` (`0` compact, else 2-space;
  `Null`->`null`; closures/handles `E-JSON-STRINGIFY`; >10MB
  `E-JSON-STRINGIFY`).
- `req` = `{method, path, query (map), headers (map lower-case), body,
  remote}`; response = `{status, headers, body}`.
- Bodies are UTF-8 `Str` (lossy like `http_get`); `Content-Length`
  required for bodies (missing = `""`); `chunked` is `400`; keep-alive for
  `HTTP/1.1` unless `Connection: close` (always `Content-Length`).

## Error codes

- `E-HTTP-URL` (bad url/redirect url), `E-HTTP-METHOD` (bad method),
  `E-HTTP-HEADER` (bad header name/value or non-str value),
  `E-HTTP-TIMEOUT` (bad timeout arg or connect/read expiry),
  `E-HTTP-CONNECT` (refused/dns/tls/io transport failure),
  `E-HTTP-REDIRECT` (too many, loop),
  `E-HTTP-OPTIONS` (bad serve/request options),
  `E-HTTP-HANDLER` (unknown handler, empty/NUL, arity !=1),
  `E-HTTP-CLOSED` (server_port on stopped),
  `E-HTTP-STATUS` (bad status 100..599),
  `E-HTTP-ROUTE` (empty pattern/path, empty `:name`),
  `E-JSON-PARSE` (invalid JSON, trailing garbage, depth),
  `E-JSON-STRINGIFY` (closures/handles, non-finite floats, depth, >10MB),
  `E-SANDBOX-NETWORK` (serve/port/stop/request in sandbox).
- Reused: `E-NET-*` (bind via A1: `ADDR-IN-USE` etc), `E-TYPE` (wrong
  handle kind, `server` named), `E-ARITY`, `E-RUNTIME` (unreachable only).
- Server statuses (not diagnostics): `400` malformed/chunked, `413`
  oversize headers/body, `408` slow (read timeout), `500` handler failure
  (safe `{"error":"internal server error"}`, `eprintln` log, keeps running).

All messages name the offending value (urls redacted past 200 chars,
bodies past 200); all are `file: "runtime", 0, 0`; none panic (gates prove).

## Limits

- Workers `1..32` (default 4); job chan `workers*4` (8..1000); 200
  concurrent tested (queues, all correct).
- Bodies `0..10MB` (default cap 1MB); headers `1024..1MB` (default 64KB,
  200 max); request line/target/method length-capped; `400/413/408`
  close (no keep-alive after errors); `500` may keep alive.
- JSON depth 64, output 10MB; 1MB parses <1s (gate-pinned; pure-Klang
  cannot).
- `DELETE/OPTIONS/GET/HEAD` bodies ignored; `chunked` unsupported (`400`).
- `Bool` erases to `Int` (JSON bools -> `1/0`, ints encode as numbers).
- `http_stop` from a worker only signals (no self-join deadlock);
  forgotten servers stop at program exit (like threads).
