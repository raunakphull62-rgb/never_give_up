# A2 — Threads, channels, signals

## Ambiguity readings (taken as specified, documented here)

- **`thread_spawn(fn_name, args_array)` takes a string name.** Klang has no
  function-reference values (functions are called, closures are values), so
  the body is a `str` naming a top-level `fn` plus an `array` of args.
  A statically-known closure in that position is check-time
  `E-THREAD-CLOSURE`; a dynamic closure (e.g. via a map, `Unknown`) is the
  same code at runtime. Empty/NUL names are `E-THREAD-UNKNOWN`. Target arity
  mismatch is `E-THREAD-ARITY` (builtin arity itself is `E-ARITY`).
- **Share-nothing for data, shared handles for OS resources.** Plain
  `Int/Float/Str/Array/Map/Struct` args/results deep-copy via `Clone`.
  `Chan` handles are freely shared (same queue, `Arc` clone) across threads.
  A1 `Listener/Conn/UdpSock` may be passed to threads by cloning the `Arc`
  (the queue's "transferring ownership"): after the move both sides hold the
  same socket; concurrent ops serialize on the internal mutex, `conn_close`
  from any thread closes for all, use-after-close is `E-NET-CLOSED`. Rule:
  move a handle to at most one worker and do not use it from the parent
  afterwards; sharing is safe (never a crash) but interleaves. `Value` is
  `Send` (all variants `Send`), the program (`MirModule`) is shared via
  `Arc`, each thread gets its own values map + fresh `CancelToken`; prints
  share the ordered `Arc<Mutex>` output. No soundness gap found, so no STOP.
- **`recv` on closed-empty is null.** All empty non-blocking cases are null
  (`is_null`): `recv` on closed-empty, `recv_timeout` on timeout or
  closed-empty, `try_recv` when empty (open or closed). `send` on closed is
  `E-CHAN-CLOSED` (never silent). `close` is idempotent (`1`).
- **`chan(0)`/rendezvous unsupported.** `chan(capacity)` requires
  `1..1_000_000`; `0` (Go-style rendezvous) is `E-CHAN-CAPACITY` — use `1`
  for minimal buffering. Negative/huge capacities are the same code.
  `recv_timeout` negative/huge is `E-CHAN-TIMEOUT` (expiry itself is null).
- **Sandbox: cap, not blanket deny.** `thread_spawn` is allowed up to 4 live
  threads in sandbox, beyond that `E-SANDBOX-THREADS` (the queue's "caps at
  4 ... or denies them" first option). All channel ops (`chan/send/recv/
  recv_timeout/try_recv/close`) deny outright in sandbox with
  `E-SANDBOX-THREADS`; signals deny with `E-SANDBOX-SIGNAL`. `thread_id`
  (like `is_null`) and `thread_join` (observing an existing handle) stay
  allowed. `KLANG_MAX_THREADS` configures the plain-mode max (default 256,
  `E-THREAD-LIMIT` beyond it).
- **Signals are polling flags.** `signal_watch("INT"/"TERM"/"HUP")`
  (case-insensitive) installs a handler that only sets an `AtomicBool`;
  `signal_pending(name)` returns `1` once then clears (`0` after). Windows
  supports only `"INT"` (`TERM`/`HUP` are `E-SIGNAL-UNSUPPORTED` there).
  Unknown names are `E-SIGNAL-UNKNOWN`.
- **`thread_join` is idempotent.** The first join blocks, caches the result
  (value or wrapped `E-THREAD-FAILED` with the cause under `related`; panics
  become `E-THREAD-FAILED`; `exit(n)` propagates unwrapped like task
  groups), the second returns the same value. Unjoined threads are reaped
  (joined, results ignored) at program exit so no OS thread leaks past the
  run; programs must still join to observe failures.

## What changed

- New file `src/stdlib/a2_threads.rs`: bounded channels (`Mutex`+`Condvar`,
  no crates), thread ids/counts/limits, signal flags via raw `signal(2)`
  (no new dependencies), `E-THREAD-*`/`E-CHAN-*`/`E-SIGNAL-*` constructors.
  `thread_spawn` needs the interpreter context, so it runs in
  `run_instrs` (like `sort_by`); the rest run in `exec_builtin`.
- `src/runtime/mod.rs`: new `Value::{Thread, Chan}` (`Arc` shared state,
  identity equality, `<thread>`/`<chan>` rendering, truthy, `thread`/`chan`
  type names in `E-TYPE`); `ExecCtx.threads` registry + reap-at-exit;
  `thread_spawn` spawn site (own values, fresh token, 8 MiB stack,
  `ActiveGuard` for live-count); `exec_builtin` arms for 11 builtins;
  `conn_close` also accepts `Chan`.
- `src/hir.rs`: `is_builtin` + arity + type checks (handle positions require
  `Unknown`; `thread_spawn` closure is `E-THREAD-CLOSURE`).
- `src/stdlib/mod.rs`: `pub mod a2_threads;`.
- `src/sandbox.rs`: `deny_threads` (`E-SANDBOX-THREADS`), `deny_signal`
  (`E-SANDBOX-SIGNAL`).
- `src/runtime/v2.rs`: new variants reject in `value_to_data` (loud, never
  silent); builtins already reject as `E-UNDEFINED` via unknown-function.
- Tests `tests/a2_gates.rs`: 27 gates (see below).
- JIT/v2: no code change needed — new builtins are `is_builtin`, so the JIT
  rejects with `unsupported ...` (`JIT-FAIL`) and v2 reports `E-UNDEFINED`;
  both pinned by gates.

## Builtin signatures (exact)

- `thread_spawn(fn_name: str, args: array) -> Thread`.
- `thread_join(t: Thread) -> value` (`E-THREAD-FAILED` naming thread+cause,
  idempotent; `exit` unwrapped).
- `thread_id() -> Int` (`0` on main, `1..` for workers; allowed in sandbox).
- `chan(capacity: int) -> Chan` (`1..1_000_000`, else `E-CHAN-CAPACITY`).
- `send(ch: Chan, v: any) -> Int` (`1`; blocks when full; `E-CHAN-CLOSED`).
- `recv(ch: Chan) -> value` (blocks when empty; null when closed-empty).
- `recv_timeout(ch: Chan, ms: int) -> value` (null on timeout/closed-empty;
  `ms 0..24h`, `0` tries once, negative/huge is `E-CHAN-TIMEOUT`).
- `try_recv(ch: Chan) -> value` (null when empty, never blocks).
- `close(ch: Chan) -> Int` (`1`, idempotent; wakes all; `conn_close` also
  accepts `Chan`).
- `signal_watch(name: str) -> Int` (`1`; `INT/TERM/HUP` case-insensitive).
- `signal_pending(name: str) -> Bool` (`1` once then clears).

## Error codes

- `E-THREAD-CLOSURE` (closure as body, check + runtime).
- `E-THREAD-UNKNOWN` (unknown fn name, empty/NUL).
- `E-THREAD-ARITY` (target arg count mismatch).
- `E-THREAD-LIMIT` (plain-mode max, default 256, `KLANG_MAX_THREADS`).
- `E-THREAD-FAILED` (join re-raises failure/panic, thread+cause named,
  cause under `related`).
- `E-CHAN-CLOSED` (send on closed).
- `E-CHAN-CAPACITY` (bad `chan` capacity).
- `E-CHAN-TIMEOUT` (bad `recv_timeout` ms; expiry itself is null).
- `E-SIGNAL-UNKNOWN` (bad name), `E-SIGNAL-UNSUPPORTED` (TERM/HUP on Windows).
- `E-SANDBOX-THREADS` (sandbox: spawn beyond 4, all channel ops),
  `E-SANDBOX-SIGNAL` (sandbox signals).
- Reused: `E-TYPE` (wrong handle kind, `thread`/`chan` named), `E-ARITY`
  (builtin arity), `E-RUNTIME` (unreachable paths only).

All messages name the offending value; all are `file: "runtime", 0, 0`
like `E-NET-*`; none panic on bad input (gates prove it).

## Limits

- Max live threads 256 (`KLANG_MAX_THREADS` overrides when positive),
  sandbox 4. Each thread 8 MiB stack (same as `spawn`).
- `chan` capacity `1..1_000_000` (queue length, not preallocated); `0`
  rendezvous rejected. `send` blocks when full, `recv` blocks when empty;
  `close` wakes all (sends fail, recvs drain-then-null) — deadlock-free.
- A1 handles across threads share the socket (`Arc` clone); concurrent use
  serializes, close-anywhere closes-everywhere. Channels share freely.
- Signals: polling only, no handlers running Klang code; `watch` clears the
  flag, `pending` polls-and-clears.
