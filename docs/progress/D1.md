## SILENT pitfalls (run exit 0, wrong vs Python/JS) — the dangerous list

Verified with `/tmp/t1/debug/klang` (exact outputs):

S1 `1 + "a"` → `"1a"` (concat, not error). `print(1 + "a")` prints `1a`.
S2 `len("é")` → `2` bytes, not 1 char. `print(len("é"))` prints `2`; `"héllo"[1]` prints `é` (char-based).
S3 `7 / 2` → `3` (truncates); `-7 / 2` → `-3` (Python floor `-4`). Verified `print(7 / 2)` → `3`, `print(0 - 7 / 2)` → `-3`.
S4 `0 - 7 % 3` → `-1` (Rust remainder, sign of dividend; Python `2`). Verified `print(0 - 7 % 3)` → `-1`, `print(7 % 3)` → `1`.
S5 `1 && 2` → `1`, `0 || 5` → `1` (Bool 0/1, not operand; short-circuit). Verified `print(1 && 2)` → `1`, `print(0 || 5)` → `1`, `print(!0)` → `1`, `print(!5)` → `0`.
S6 `print(true)` → `1`, `print(false)` → `0` (not `True`/`False`).
S7 `sort(a)` returns copy; input unchanged. Verified `sort([3,1,2])` → `[1, 2, 3]`, input stays `[3, 1, 2]`.
S8 `push(a, v)` returns new length (Int), not array. Verified `push([1], 2)` prints `2`, array becomes `[1, 2]`.
S9 `m[0]` → first key `"a"` (positional, not KeyError). Verified `{"a":10,"b":20}[0]` → `a`.
S10 `args()` excludes prog name; empty with no args. Verified `len(args())` → `0`.
S11 `read_line()` is `""` at EOF and for empty line (need `is_eof()`). Verified empty stdin: `read_line() == ""` → `1`, `is_eof()` → `1`.
S12 `env("X")` missing → `""` (not None, indistinguishable from empty). Verified `env("KLANG_NOPE_XYZ") == ""` → `1`.
S13 struct/array/map params pass-by-value (caller unchanged). Verified `f(q)` → `99`, `q.x` stays `1`.
S14 `fn main()` (no arrow) always exits 0, discards value. Verified `fn main() { print(7) }` prints `7`, exit 0.
S15 exit codes wrap 8-bit (`256`→`0`, `-1`→`255`). Keep 0..125.
S16 `format("a", 1)` → `"a 1"` (space-joined, not Python format). Use `sprintf("{} + {}", [1, 2])` → `"1 + 2"`.
S17 `spawn`/`run` argv-only, no shell/glob/pipe (silent no-expansion). Verified `spawn("echo", ["hi"])["status"]` → `0`.
S18 `len()` bytes vs `s[i]`/`slice()` chars. Verified `len("é")` → `2`, `slice("é", 0, 1)` → `é`; `len("héllo")` → `6`, `len("héllo".chars())` → `5`, `slice("héllo", 1, 3)` → `él`. Trap: `slice(s, 0, len(s))` works for ASCII but `E-RUNTIME` OOB for non-ASCII — use `len(s.chars())`.
S19 `==` value equality; maps order-sensitive. Verified `[1,2]==[1,2]` → `1`, `[1,2]==[1,3]` → `0`; same struct value → `1`; `{"x":1,"y":2}=={"y":2,"x":1}` → `0` (Python `True`). JS reference-expecting models note: Klang compares by value, not reference.
S20 truthiness: literal `if ""`/`if []` is loud `E-TYPE`, but same value via `unknown` (`m["k"]`) runs silent falsy. Verified `m={"s":"","a":[1]}; if m["s"]` → falsy `0`, `if m["a"]` → truthy `1`. Use `== ""` / `len() == 0` explicitly.

## Top 10 most confusing diagnostics

All verified post-D1b with the real compiler:

1. `with open(..)` / `elif` → `E-PARSE` "expected a `\"key\"` or `key` in
   map literal" (mentions maps for control-flow keywords).
2. `if True` (capitalized) → `E-PARSE` "expected field name";
   but `print(True)` → `E-UNDEFINED` "undefined variable `True`" (same word,
   different codes by position).
3. `f"hi {x}"` → `E-PARSE` "expected `)`" (no hint that f-strings do not exist).
4. `print("a", "b")` → `E-PARSE` "expected `)`" (no hint: 1 arg only, use `format`).
5. `a[1:2]` → `E-PARSE` "expected `]`" (no hint: use `slice(a, 1, 2)`).
6. `1 in [1,2]` → `E-PARSE` "expected `{`" (no hint: use `.contains()`).
7. `m.field` on maps → `E-TYPE` "field base: want struct, got map" (correct
   but Python users need `m["field"]` in fixes).
8. `1 == true` → `E-TYPE` "`==` operands: want i32, got bool" (names one side
   as expected; real rule is same-type-or-int/float-mix).
9. `set_env("", _)` → Rust panic, exit 101, no diagnostic (see bug above).
10. `1 < 2 < 3` → `E-TYPE` "comparison operands: want i32/f64/str, got bool"
    (parses as `(1 < 2) < 3`; Python chains, Klang does not — use `(1 < 2) && (2 < 3)`).

Fixed since D1 (no longer confusing): `klang check --json` exists (one `{"diagnostics":[...]}` object, exit 0/1, follows imports, respects `--strict`); `klang run --sandbox` exists (no longer silently ignored; denials are `E-SANDBOX-*`); `klang mcp` now fails loudly with `E-CLI-REMOVED` (no longer serves stdio).
