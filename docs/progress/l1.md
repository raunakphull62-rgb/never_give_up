# L1 — Datetime and compression (library stage)

## Ambiguity readings (taken as specified, documented here)

- **Canonical instant is an `Int` of epoch milliseconds.** The queue offers
  `dt_now() -> {epoch_ms, ...}` or a consistent representation; this stage
  chooses a plain `Int` (like the existing `now_ms`), so every datetime
  builtin takes/returns `Int` millis. No new `Value` variant, no handles.
- **No bytes type: strings are UTF-8, compressed bytes are hex or files.**
  Like A1 (`conn_read` lossy UTF-8 + `conn_read_hex`), string forms
  (`gzip_compress`/`gzip_decompress`, `zlib_compress`/`zlib_decompress`)
  carry exact bytes as lowercase hex; binary data goes through files
  (`gzip_file`/`gunzip_file`, `zlib_file`/`unzlib_file`). No native
  `hex_encode`/`hex_decode` duplicates (the pure-Klang `hex` package owns
  those names; a native clash would trip `W-SHADOW`).
- **`dt_format` is UTC-only.** The queue lists `%z` among the verbs; since
  named zones are unsupported, `%z` always renders `+0000` and the whole
  format is the UTC wall clock. `%f` is milliseconds (`000`..`999`, three
  digits), not chrono's nanosecond form. `%%` yields a literal `%`.
- **`dt_add` map keys and unknown keys.** Only `days`, `hours`, `minutes`,
  `seconds`, `ms` are read (all optional `Int`, default 0); unknown keys
  are ignored for forward compatibility. Non-`Int` values are `E-TYPE`.
- **`dt_diff_ms(a, b)` is `a - b`** (positive when `a` is later).
- **`dt_parts` weekday/yday convention.** `weekday` is `0`=Sunday..`6`=
  Saturday (strftime `%w`); `yday` is `1`..`366` (strftime `%j`). The map
  also carries `millis` (`0`..`999`) beyond the queue's listed keys so
  sub-second instants round-trip without loss.
- **`dt_parts_offset` range.** Fixed offsets `-1080`..`+1080` minutes
  (±18h, covering all real zones); anything else is `E-TIME-RANGE`.
- **`zlib` file names.** The queue's `zlib_* equivalents` of
  `gzip_file`/`gunzip_file` are spelled `zlib_file`/`unzlib_file`
  (parallel to gzip/gunzip). `tar_extract_limit(tar, dir, max_bytes)` is
  the documented "option" for the 256 MB default cap (plus
  `tar_extract(tar, dir)` with the default).
- **Spans are explicit no-location** (`file: "runtime", 0, 0`) like the
  existing `E-NET-*`/`E-THREAD-*` family (per limitations), not per-call
  source spans.
- **Sandbox.** Datetime and string-compress forms are pure computation and
  stay allowed in sandbox (like `is_null`/`thread_id`). File forms
  (`gzip_file`, `gunzip_file`, `zlib_file`, `unzlib_file`, `tar_create`,
  `tar_extract`, `tar_extract_limit`) follow the existing temp-dir rule
  (`E-SANDBOX-FILE` outside the temp dir), per the queue's "file-based
  functions follow the sandbox temp-dir rule".
- **Backend parity.** No `allowlist.toml` change: the parity corpus covers
  `tests/parity/*.klang` + `examples/*.klang`, and this stage adds no
  programs there (`examples/apps/logship/` is outside the parity scope).
  JIT loud-rejects every new builtin as `unsupported` (int-only JIT links
  no builtins) and v2 reports `E-UNDEFINED`; both are pinned by new gates,
  mirroring A1/A2 ("no code change needed").
- **10 MB strings vs the 1M `repeat` cap.** B1 `repeat`/pads cap output at
  1M chars, so a 10 MB Klang string cannot be built with `repeat` in-test.
  The 10 MB string gate uses direct stdlib calls plus a `read_file`-fed
  Klang string; the 10 MB file gate uses Rust-created files plus Klang
  file builtins. Limits (`32 MB` string input, `64 MB` string output,
  `256 MB` file/tar) all clear 10 MB.

## Builtin signatures (exact)

Datetime (`Int` = epoch millis UTC):
- `dt_now() -> Int`.
- `dt_parse_iso(s: str) -> Int` (RFC-3339 `Z`/`±HH:MM`, `±HHMM`,
  `YYYY-MM-DDTHH:MM:SS[.frac]`, `YYYY-MM-DD HH:MM:SS[.frac]`,
  `YYYY-MM-DD` midnight UTC).
- `dt_format(ms: int, pattern: str) -> Str` (verbs `%Y %m %d %H %M %S %f
  %z %a %A %b %B %j %p`, `%%`; UTC).
- `dt_add(ms: int, delta: map) -> Int` (`{days, hours, minutes, seconds,
  ms}`, all optional `Int`).
- `dt_diff_ms(a: int, b: int) -> Int` (`a - b`).
- `dt_parts(ms: int) -> Map` (`{year, month, day, hour, minute, second,
  millis, weekday, yday}`, UTC).
- `dt_parts_offset(ms: int, offset_minutes: int) -> Map` (same shape,
  wall clock at the fixed offset; `-1080`..`+1080`).
- `dt_from_parts(year: int, month: int, day: int, hour: int, minute: int,
  second: int) -> Int` (UTC; `year 1..9999`).
- `dt_local_offset_minutes() -> Int` (host OS offset, minutes).
- `dt_is_leap(year: int) -> Bool` (`1`/`0`, any year).
- `dt_days_in_month(year: int, month: int) -> Int` (`28`..`31`).

Compression (hex = lowercase):
- `gzip_compress(s: str) -> Str` (hex), `gzip_decompress(hex: str) -> Str`.
- `gzip_file(src: str, dst: str) -> Int` (output bytes),
  `gunzip_file(src: str, dst: str) -> Int`.
- `zlib_compress(s: str) -> Str`, `zlib_decompress(hex: str) -> Str`.
- `zlib_file(src: str, dst: str) -> Int`,
  `unzlib_file(src: str, dst: str) -> Int`.
- `tar_create(src_dir: str, out_path: str) -> Int` (`1`).
- `tar_extract(tar: str, dest_dir: str) -> Int` (`1`, 256 MB cap).
- `tar_extract_limit(tar: str, dest_dir: str, max_bytes: int) -> Int`
  (`1`; limit `0`..1 GiB).

## Error codes

- `E-TIME-PARSE` (`dt_parse_iso` unparseable input; names the input).
- `E-TIME-RANGE` (bad date parts incl. Feb 30/month 13/hour 25, bad
  `dt_days_in_month` month, bad offset, `dt_add`/`dt_diff_ms` overflow,
  out-of-chrono-range epoch; names the value).
- `E-TIME-PATTERN` (bad `dt_format` verb or trailing `%`; names pattern).
- `E-COMPRESS-CORRUPT` (odd-length/bad-digit hex, invalid gzip/zlib,
  non-UTF-8 string output, corrupt tar; names redacted input/path).
- `E-COMPRESS-TOO-LARGE` (over string 32/64 MB or file/tar 256 MB caps,
  bad `tar_extract_limit` limit; names the value).
- `E-COMPRESS-UNSAFE-PATH` (tar entry absolute/`..`/symlink/hardlink;
  names the entry).
- Reused: `E-TYPE` (wrong operand kinds, handle-style names),
  `E-ARITY` (arity), `E-IO-NOT-FOUND`/`E-IO-*` (missing/unreadable file
  operands via `file::map_io_error`), `E-SANDBOX-FILE` (file forms outside
  the temp dir in sandbox).

All messages name the offending value (hex/patterns redacted past 200
chars); all are `file: "runtime", 0, 0`; none panic on bad input (gates
prove it).

## Limits

- String compress input 32 MB, string decompress output 64 MB; file
  input/output and tar extraction default 256 MB (option via
  `tar_extract_limit`, max 1 GiB). Zip-bomb safe: decompressors `take`
  one byte past the cap before allocating more.
- `dt_from_parts` years `1`..`9999`; `dt_parts_offset` ±18h; local offset
  read from the OS (no tz database); named zones unsupported.
- `tar_create` archives with relative names (`append_dir_all(".", dir)`);
  extraction creates the destination, rejects absolute/`..`/link entries,
  pre-checks header sizes against the cap.
