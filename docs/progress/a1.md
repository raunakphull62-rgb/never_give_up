# A1 — Sockets (TCP, UDP, DNS)

## Ambiguity readings (taken as specified, documented here)

- **Null without a literal.** Klang has no `null` literal and no bytes
  type (`Value` is `Int/Float/Str/Array/Map/Struct/Closure`; `print(null)`
  is `E-UNDEFINED` in docs). `tcp_accept_timeout` (`Conn or null`) and
  `conn_read_line` (`Str, null at close`) therefore return a new
  `Value::Null` (renders `null`, falsy, `==` only to null) with **no new
  syntax**. Test it with the new `is_null(x) -> Bool` builtin (`1` for
  null, else `0`); `str(null)` is `"null"`. No existing test used `null`
  as an identifier, so nothing breaks. Future A2 `recv_timeout` can reuse
  the same `Null` + `is_null` idiom.
- **No bytes type: UTF-8 + hex.** Strings are UTF-8 (lossy on
  `conn_read`/`udp_recv_from`, like `http_get` bodies). Exact bytes go
  through `conn_read_hex` / `conn_write_hex` (lowercase hex). General hex
  helpers already exist as the pure-Klang `hex` package (`hex_encode` /
  `hex_decode`); no native duplicates are added (a same-named native
  would trip `W-SHADOW` and break the package parity self-test).
- **Close Story.** Only `conn_close` is in the queue list, but listeners
  and UDP socks must not leak. `conn_close` is polymorphic: it accepts a
  `Conn`, `Listener` or `UdpSock` (any handle) and is idempotent
  (returns `1`). Handles also close on drop, so program exit closes
  whatever the program forgot. No `listener_close` / `udp_close` names
  are added.
- **`udp_recv_from` timeout is an error.** The queue signature
  `udp_recv_from(sock, max_bytes, timeout_ms) -> {data, host, port}` does
  not say what timeout does. It is `E-NET-TIMEOUT` (like `conn_read`
  with a deadline), never silent. `tcp_accept_timeout` stays the only
  timeout-returns-null case.
- **`tcp_connect` timeout 0 means blocking.** `timeout_ms == 0` uses a
  blocking `connect` (no deadline); positive uses `connect_timeout`.
  Negative is `E-NET-IO`. `conn_set_timeout(c, 0)` clears deadlines
  (blocking); negative is `E-NET-IO`.

## Builtin signatures (exact)

- `tcp_listen(host: str, port: int) -> Listener` (port `0` = any;
  `0..65535`, else `E-NET-ADDR-INVALID`).
- `listener_port(l: Listener) -> Int`.
- `tcp_accept(l: Listener) -> Conn` (blocking).
- `tcp_accept_timeout(l: Listener, ms: int) -> Conn | Null` (`Null` on
  timeout; `ms >= 0`, `0` = try once).
- `tcp_connect(host: str, port: int, timeout_ms: int) -> Conn`
  (`timeout_ms == 0` = blocking).
- `conn_read(c: Conn, max_bytes: int) -> Str` (lossy UTF-8; `""` at peer
  close; `max_bytes 0..10 MB`).
- `conn_read_line(c: Conn) -> Str | Null` (strips one trailing `\n` and
  one `\r`; `""` for an empty line; `Null` at peer close; a final partial
  line without `\n` is returned once, next call is null).
- `conn_read_hex(c: Conn, max_bytes: int) -> Str` (lowercase hex; `""` at
  peer close).
- `conn_write(c: Conn, s: str) -> Int` (bytes written).
- `conn_write_hex(c: Conn, hex: str) -> Int` (bytes written; odd length /
  bad digit is `E-NET-IO`).
- `conn_close(h: Conn | Listener | UdpSock) -> Int` (`1`, idempotent).
- `conn_set_timeout(c: Conn, ms: int) -> Int` (`1`; `0` clears).
- `conn_peer(c: Conn) -> Str` (`"ip:port"`).
- `udp_bind(host: str, port: int) -> UdpSock` (port `0` = any).
- `udp_send_to(sock: UdpSock, host: str, port: int, s: str) -> Int`.
- `udp_recv_from(sock: UdpSock, max_bytes: int, timeout_ms: int) -> Map`
  (`{data: str, host: str, port: int}`; timeout is `E-NET-TIMEOUT`).
- `dns_lookup(host: str) -> Array<Str>` (sorted, deduped IP strings).
- `is_null(x: any) -> Bool` (`1` for null, else `0`; allowed in sandbox).

## Error codes

- `E-NET-REFUSED` (connect refused; message names `host:port`).
- `E-NET-TIMEOUT` (connect/read/write/recv deadlines; negative timeout
  args are `E-NET-IO`, not timeout).
- `E-NET-ADDR-INVALID` (bad host/port: empty/NUL host, port outside
  `0..65535`, unbindable address).
- `E-NET-ADDR-IN-USE` (bind to a held port; message names the port).
- `E-NET-CLOSED` (locally-closed handle used again; peer close is `""` /
  null, never this code).
- `E-NET-IO` (other IO: negative/huge `max_bytes` (`>10 MB`, `>64 KiB`
  for UDP), bad hex, read/write failures).
- `E-NET-DNS` (`dns_lookup` failures and `tcp_connect`/`udp_send_to`
  resolve failures; message names the host).
- `E-SANDBOX-NETWORK` (all of the above under `klang run --sandbox`).
- Reused: `E-TYPE` (wrong handle kind, `listener`/`conn`/`udpsock` named),
  `E-ARITY` (arity), `E-RUNTIME` (unreachable paths only).

All messages name the offending value (ports/hosts in `host:port` form;
hex payloads redacted past 200 chars); all are `file: "runtime", 0, 0`
like the existing `E-NET-*` (explicit no-location, per limitations);
none panic on bad input (gates prove it).

## Limits

- `conn_read` / `conn_read_hex` cap `10 MB`; UDP cap `64 KiB`; line
  buffer aborts past ~10 MB with `E-NET-IO` (no bomb).
- `conn_read` is one syscall (short reads return early; callers loop for
  exact sizes). `conn_read_line` buffers leftovers shared with `conn_read`
  (coherent).
- Handles are `Send` (`TcpListener`/`TcpStream`/`UdpSocket` in
  `Arc<Mutex<...>>`); A1 is still single-threaded (blocking calls only).
- No `listener_close` / `udp_close` names; use polymorphic `conn_close`.
- No native `hex_encode` / `hex_decode`; use the `hex` package + the
  `conn_*_hex` pair.

## Tests

`tests/a1_gates.rs` (29 tests, loopback + port 0 only): echo round trip,
line variants (`\n`, empty, `\r\n`), close-is-null, hex binary safety
(`00ff48c3a9`), peer naming, accept-timeout null-then-success, 1 MB in
16×64 KB chunked rounds (one big write would deadlock single-threaded
buffers), UDP Rust-level round trip + Klang timeout shape, DNS
`localhost`, `is_null` semantics, port reuse after close, blocking
`tcp_accept` with a Rust client thread, every `E-NET-*` code, wrong-type
`E-TYPE` (static + dynamic with handle-kind names), hostile no-panic
(NUL hosts, huge sizes, bad hex, empty reads), arity/type static checks,
sandbox denial (creation + existing-handle use; `is_null` allowed), JIT
loud reject, v2 `E-UNDEFINED`.
